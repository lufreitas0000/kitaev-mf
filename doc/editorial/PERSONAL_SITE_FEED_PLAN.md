## 1. Epistemic Promotion Gate (Front 1 / Front 2 $\to$ Public Website Feed)

Before any `kitaev-mf` topic is toggled to `visible: true` on the personal site feed:

1. **Source Grounding:** Every displayed equation, solver speedup, or scaling exponent traces back to a concrete versioned artifact in `kitaev-mf` (`src/`, `test/`, `data/processed/benchmarks/**/*.dat` with `#` provenance header, or `doc/rnd/` + `doc/labbook/`).
2. **Epistemic Status Tagging:** Each post declares an explicit frontmatter `evidence_status` (e.g., `expository-synthesis`, `verified-algebraic-and-numerical`, `empirical-fit-with-open-proof`, or `erratum-and-open-question`) and distinguishes:
   - Exact algebraic proofs & operator identities (`K-001`–`K-007`, KKT stationarity, idempotency freeze proof);
   - Audited finite-dimensional numerical benchmarks (`K-011`–`K-023`, Wilson 95% CIs, hardware throughput);
   - Finite-mesh empirical regressions (`c_MF = 2.5921 \pm 0.0034`, $\|\boldsymbol{\lambda}^*\|_2 \approx \sqrt{5} h$) with open analytical derivations (`IDEA-001`);
   - Refutations, errata, and open prerequisites (`K-019-A`, `AH-04` Arm A, naive warm-start freeze, unconverged KKT saddles).
3. **Cross-Repository Attribution (`ADR-003`):** Any future figure comparing `scMFT` against Spin-ED, 2-RDM SDP, or exact lattice resolvents must read from a verified `data/external/<source_repo>/` dataset (`scripts/sync_external_data.py --verify`) and credit the producing sister repository (`kitaev-numerics` or `kitaev-walk-geometry`).
4. **PR & Staging Workflow in `personal-website`:** Draft new files with `visible: false` first, compile `.svg` figures locally from `kitaev-mf` `.dat`/TikZ sources, verify KaTeX/Markdown rendering and Rule 03 privacy regex checks, and promote `visible: true` only after visual inspection.

## 2. Reproducible `.dat` / TikZ $\to$ `.svg` Figure Pipeline

To keep plots crisp in both light and dark modes on the personal website and strictly synchronized with `doc/labbook/figures/`:

1. **Source Data / TikZ:** Export tabular curves strictly from `data/processed/benchmarks/**/*.dat` (generated by `scripts/generate_benchmarks.py` or milestone scripts) and standalone TikZ/PGFPlots templates in `doc/labbook/figures/`.
2. **Standalone PDF $\to$ Vector SVG Conversion (Run in a scratch directory, commit only final `.svg` into `personal-website/site/assets/img/gallery/feed/`):**
   ```bash
   # Compile standalone TikZ/PGFPlots wrapper referencing kitaev-mf .dat tables
   pdflatex -halt-on-error -interaction=nonstopmode fig_standalone.tex
   # Prefer dvisvgm (clean path outlines + embedded stroke scaling) or pdf2svg
   dvisvgm --pdf --no-fonts -n -o kitaev-mf-<topic>.svg fig_standalone.pdf
   # Alternative fallback: pdf2svg fig_standalone.pdf kitaev-mf-<topic>.svg
   ```
3. **Website Frontmatter Reference Format:** Every figure enters `figures:` as:
   ```yaml
   figures:
     - src: "../../assets/img/gallery/feed/kitaev-mf-<topic>.svg"
       alt: "<Concise physical/numerical alt text>"
       kind: "labeled-svg"
       max_width: "100%"
   ```
4. **Visual Hygiene Checklist:** Explicit axis units (`|K| = 1`), explicit curve legends, neutral/high-contrast line colors (no unreadable pale yellow on white), and explicit caption distinction between exact curves, discrete solver sweeps, and fitted power laws.
